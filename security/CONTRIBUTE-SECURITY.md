# Security Contribution Guide

This file is for security professionals and experts who want to improve the system.

## What to contribute

- stronger security guardrails
- better user education
- stronger audit checklists
- advanced threat modeling
- compliance maturity guidance
- more robust incident response plans
- industry-specific security guidance

## How to contribute

- explain assumptions clearly
- keep advice relevant to non-technical users
- provide plain-language guidance when possible
- include warnings where a professional review is necessary
- explain the tradeoff between convenience and security

## Recommended format

For each new module, use:
- why it matters
- what problem it solves
- how to implement it
- what to watch for
- when to involve a professional

## Community value

The goal is to help the project be safer and more practical, not perfect or rigid. Security should accelerate trust, not block opportunity.
