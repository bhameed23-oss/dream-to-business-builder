# User-Facing Lifecycle Journey

This file defines the actual user journey through the lifecycle product.

## A. Identify the problem
The user starts by telling the system:
- what they are trying to build or improve
- what phase they are in
- what outcome they want next

## B. Understand the current state
The system asks a small set of guided questions and creates a baseline:
- business identity
- customer profile
- current process
- current risk
- current tools
- current bottlenecks

## C. Recommend the starting phase
The system identifies the most relevant lifecycle phase using the shared business profile and the user’s goals.

## D. Show the dashboard
The dashboard includes:
- current phase
- business health summary
- top priorities
- risk triggers
- next best actions
- integration overview

## E. Guide the next step
The user sees the most relevant next actions, ordered by impact and urgency.

## F. Support human review
If the business is risky or complex, the product explicitly recommends a professional review before important actions proceed.

## G. Continue across phases
As the business changes, the dashboard updates. The user can revisit any phase and continue from the same business profile.

## Why it matters

This makes the product feel like a guided operating system that supports real-world movement instead of a static set of template prompts.
